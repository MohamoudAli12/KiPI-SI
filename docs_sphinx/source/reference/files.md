# Files KiPI-SI reads and writes

## File reference

```{list-table}
:header-rows: 1
:class: kipi-table

* - File
  - What it is
* - `<schematic>.pdn.json`
  - The board's power tree, generated by [Tomachie.com](https://tomachie.com) from the schematic and the parts' datasheets: every power rail with its voltage and where it comes from; each regulator with its type, efficiency, quiescent current, dropout and input range; the parts in series between rails (fuses, ferrites, inductors, load switches, 0 Ω links) with their DC resistance; and every load with its typical and maximum current and the lowest supply voltage its datasheet allows. **Import…** in the DC setup reads it. It saves hours of reading datasheets and typing values in.
* - `<board>.kipi_si-setup.yml`
  - The setup: ticked nets, VRMs, loads, series links, mesh, copper and thermal settings, capacitor models, probes and the sweep, in YAML. Saved next to the board on **Save** and on every solve.
* - `<board>.kipi_si-setup.json`
  - A setup saved by KiPI-SI before 0.8.0. It still opens, with a warning, when there is no `.yml` setup; the next save writes the `.yml` and leaves the JSON file alone. JSON setups are deprecated: a future KiPI-SI will stop reading them.
* - `pi_parts.yml`
  - The {ref}`parts library <parts-library>`: currents, resistances, ratings and roles by part number, for **Auto-fill rail…**. Read from beside the board and from KiPI-SI's folder in the user's config; written to (beside the board) only when you let KiPI-SI add the parts it had no numbers for, or to `pi_parts.missing.yml`.
* - `*.kipi_si-load.yml`
  - A {ref}`load model <load-models>`: one part's supplies, with their currents, tolerances and AC targets.
* - `*.kipi_si.json.gz`
  - A board snapshot (copper, stackup, pads, vias, parts).
* - `*.kipi_si-dc-results`
  - A saved DC solve: JSON and NumPy arrays in a zip.
* - `*.kipi_si-dc-thermal-results`
  - A saved electro-thermal solve (DC with the board temperature), in the same format.
* - `*.kipi_si-results`
  - DC results saved by KiPI-SI 0.7 and earlier, as Python pickles, which can run code; KiPI-SI asks before it opens one, and they are deprecated.
* - `*_noise_report_*.html`, `.pdf`
  - Coupled Noise report, written with the Report button to `kipi_si_reports/`
* - `*.kipi_si-noise-results`
  - Saved Coupled Noise results, every solved aggressor (Save results… / Open results… in Coupled Noise mode)
* - `*_si_report_*.html`, `.pdf`
  - Signal Integrity report of a channel, written with the Report button to `kipi_si_reports/`
* - `*.kipi_si-si-results`
  - Saved Signal Integrity results: every solved channel and the Quick Scan
* - `*.s2p`, `*.s4p`
  - A channel's S-parameters (Touchstone), from Export Touchstone…
* - `*.kipi_si-ac-results`
  - Saved AC results, every rail solved, in the same format.
* - `<board>_kipi_si_report_<date>_<time>.html`
  - The DC HTML report.
* - `<board>_<rail>_ac_report_<date>_<time>.html`
  - An AC rail's HTML report.
* - `*.csv`
  - DC tables, or an AC rail's impedance.
* - `*.vtm`
  - DC 3D results for ParaView.
* - KiPI-SI's environment
  - Standalone only: the packages the launcher installed, in `%LOCALAPPDATA%\KiPI-SI\venv` (Windows), `~/Library/Application Support/KiPI-SI/venv` (macOS) or `~/.local/share/kipi_si/venv` (Linux), with the launcher's logs in `logs` beside it. `python kipi_si_launcher.py --reset` deletes it.
* - `kipi_si-<user>.lock`, `kipi_si-standalone-<user>.lock`
  - In the temporary folder while the plugin, or standalone KiPI-SI, is open, so a second one brings the first to the front. It names the owner's process, so one left behind by a crash is ignored.
* - `<board>.kicad_prl`
  - KiCad's own local project settings. `kicad-cli` may create it next to the board the first time it exports {ref}`part models <part-models>`, if the project has none yet.
* - `kipi_si-<date>-<time>-<pid>.log`
  - The session log, in `kipi_si/` under the temporary folder, with a matching `.crash.log`. The last 15 sessions are kept.
```
